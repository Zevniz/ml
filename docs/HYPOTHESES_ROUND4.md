# Раунд 4: границы модельного улучшения и operating point

Раунд 4 проверял, остался ли измеримый model-side gain после принятия reporter
fingerprint, или дальнейший выигрыш следует искать только в operating point `k`.
Протокол сохранялся неизменным:

* четыре хронологических фолда с validation block по 7 446 строк, expanding prefix
  и inner holdout для выбора числа итераций;
* вариант `fpte` — принятый набор reporter-fingerprint признаков;
* single-model runs с seed'ами `42, 2026`, full-ensemble blends с seed'ами
  `42, 2026, 777`;
* F1 считается top-k правилом, где `k = m × (истинное число позитивов блока)`.

## Model-side проверки

Базовая single-model точка для сравнения — shipped `lgb_neutral`:
ROC AUC `0.79451`, PR AUC `0.41127`, F1 при `m=1.8` `0.42040`.

| Preset | Mean ROC AUC | Mean PR AUC | Mean F1 m=1.8 | Вердикт |
|---|---:|---:|---:|---|
| `lgb_mcs80` (`min_child_samples=80`) | 0.79598 | 0.41388 | 0.42071 | отклонён: внутри fold noise |
| `lgb_leaves96` | 0.79224 | 0.40873 | 0.42012 | отклонён |
| `lgb_ff60` (`colsample=0.60`) | 0.79400 | 0.41065 | 0.41988 | отклонён |
| `lgb_lr015` | 0.79376 | 0.41025 | 0.41913 | отклонён |
| `lgb_leaves24` | 0.79264 | 0.40835 | 0.41740 | отклонён |
| `lgb_hl210` (recency, half-life 210) | 0.79138 | 0.40567 | 0.41827 | отклонён |
| `lgb_hl105` (recency, half-life 105) | 0.79119 | 0.40542 | 0.41467 | отклонён |

Recency weighting ясно ухудшает LightGBM, в отличие от CatBoost, где `cat_recent`
помогает. Все остальные presets находятся в пределах `±0.001` F1 от shipped
модели, то есть внутри fold noise. Ничего из этой группы не принято.

## `ip_country_id`

Мотив для отдельной проверки — жёсткий domain shift. Train на `99.4%` состоит из
country 23; country 11 встречается всего в 285 строках, но имеет target mean `0.92`,
стабильный на всех 12 месяцах. В test country 11 занимает 2 969 из 7 446 строк
(`40%`), а апрель и май 2026 почти полностью состоят из country 11.

Country 11 нельзя использовать как prior `0.92`: в hidden test ровно 990 позитивов,
поэтому 2 969 строк с такой вероятностью невозможны. Если предположить train-like
prevalence в мартовской части, для апреля/мая получается около `0.12`, то есть
почти равномерный prior.

Измеренные варианты против `fpte` (`0.79451 / 0.41127 / 0.42040`):

* raw feature `fpte_ip`: `0.79450 / 0.41397 / 0.41968`;
* OOF TE `fpte_ipte`: `0.79502 / 0.41499 / 0.41968`.

PR AUC вырос примерно на `0.004`, но F1 упал на `0.0007`. Вариант отклонён:
F1 gain отсутствует, а CV-фолды не могут измерить режим, который действительно
важен на test, поскольку train не содержит country-11-dominated блока.

## Проверки полного ансамбля

Для равновесного 4-компонентного blend с 3 seed'ами baseline при `m=1.8` равен
`0.42516`.

Добавление пятой компоненты дало:

| Дополнительная компонента | F1 m=1.8 |
|---|---:|
| `+lgb_mcs80` | 0.42524 |
| `+lgb_fpte_ipte` | 0.42588 |
| `+lgb_fpte_ip` | 0.42580 |
| `+lgb_leaves96` | 0.42615 |
| `+lgb_ff60` | 0.42596 |
| `+cat_hl105` | 0.42398 |
| `+mcs80+ipte` | 0.42556 |

Все различия находятся в пределах `+0.001` и отклонены как noise.

Комбинационные правила:

| Правило | F1 m=1.8 |
|---|---:|
| Усреднение вероятностей | 0.42516 |
| Усреднение logits | 0.42571 |
| Усреднение standardized logits | 0.42532 |
| Rank average | 0.42357 |

Оставлено простое усреднение вероятностей. Дополнительная проверка числа seed'ов
дала `0.42632` для 1 seed, `0.42590` для 2 seed'ов и `0.42516` для 3 seed'ов
(среднее по всем подмножествам). Дополнительные seed'ы не улучшают top-k F1:
fold noise floor составляет примерно `±0.001–0.002`, а различия меньше `~0.005`
неразрешимы на этой CV.

## Operating point `k`

Так как число позитивов test известно ровно (`990`), решение имеет вид

```text
F1(k) = 2 * TP(k) / (k + 990).
```

Следовательно, `k` — единственный свободный параметр decision rule.

CV rate curve на reporter-fingerprint scores:

| m | 1.6 | 1.7 | 1.8 | 1.9 | 2.0 |
|---|---:|---:|---:|---:|---:|
| F1 | 0.4190 | 0.4232 | 0.4251 | 0.4252 | 0.4231 |

Кривая плоская, поэтому её optimum нельзя надёжно разрешить офлайн.

### Break-even test

Расширение `k` выгодно только пока marginal precision выше `F1 / 2`. На фолдах
отношение marginal precision в диапазоне `[1.8, 2.0]` к средней precision при
`m=1.8` равно `0.536 / 0.749 / 0.687 / 0.419` для folds 4/3/2/1, среднее
`0.60`. Leaderboard point с F1 `0.489` при `k=1782` означает `TP=678` и average
precision `0.380`; для расширения нужен ratio выше `0.643`. Поэтому направление
остаётся borderline и офлайн не разрешается.

### Calibration-based estimator

Блендовые вероятности сдвигаются единым logit offset так, чтобы их сумма совпала
с известным числом позитивов, после чего максимизируется
`2 * sum(top-k p) / (k + P)`. На фолдах estimator выбирает
`m = 1.70 / 1.90 / 1.85 / 1.95` для folds 4/3/2/1 против истинных optimum
`1.85 / 1.95 / 2.10 / 1.30`; во всех случаях он находится в пределах `0.005 F1`
от fold optimum.

На test estimator выбирает `m=1.60` (`k=1584`), причём предсказанная кривая плоская
между `m=1.4` и `m=1.9`.

## Рекомендация

Раунд 4 не нашёл дальнейшего измеримого model-side gain. Рекомендован leaderboard
probe с одинаковым ranking и четырьмя значениями `k`:

| Файл | k | m |
|---|---:|---:|
| `submissions/submission_equal4_m140_fp.csv` | 1386 | 1.4 |
| `submissions/submission_equal4_m160_fp.csv` | 1584 | 1.6 |
| `submissions/submission_equal4_m180_fp.csv` | 1782 | 1.8 |
| `submissions/submission_equal4_m200_fp.csv` | 1980 | 2.0 |

Все четыре файла используют один ranking и отличаются только `k`. Reported F1 при
известном `k` позволяет точно восстановить `TP(k)`, поэтому две загрузки определят
slope. До появления leaderboard evidence `solution.py` сохраняет `m=1.8`.

## Как запустить

```bash
python src/make_rate_probe.py
```

Скрипт читает cached reporter-fingerprint test scores и пишет четыре файла:
`submission_equal4_m140_fp.csv` (`k=1386`), `submission_equal4_m160_fp.csv`
(`k=1584`), `submission_equal4_m180_fp.csv` (`k=1782`) и
`submission_equal4_m200_fp.csv` (`k=1980`).

Для воспроизведения single-model части раунда `src/exp_features.py` содержит
`LGB_PRESETS`/`CAT_PRESETS` и weighted LightGBM fit.
