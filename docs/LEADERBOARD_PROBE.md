# Лидерборд-проба operating point `k`

Число позитивов в hidden test известно ровно: all-ones submission даёт
`F1 = 0.2347083926`, откуда `P = 7446 * F1 / (2 - F1) = 990`. Значит для любого
top-k предсказания

```text
F1(k) = 2 * TP(k) / (k + P),   P = 990   =>   TP(k) = F1(k) * (k + 990) / 2.
```

То есть каждая загрузка с известным `k` восстанавливает точное число верно
угаданных позитивов `TP(k)`, а это уже прямое измерение кривой качества
ранжирования, а не оценка по CV. Офлайн CV на этом решении не различает `m` в
диапазоне `1.6–1.9` (F1 `0.4190 / 0.4232 / 0.4251 / 0.4252`, разница внутри fold
noise), поэтому operating point был измерен на лидерборде.

Проба сделана двумя семействами файлов, внутри каждого семейства **ранжирование
одинаковое** и меняется только `k`:

* `legacy` — исходный equal-weight blend четырёх компонент (`artifacts/probs_test.npz`,
  seed-average 42/2026/777), то самое ранжирование, которое дало `0.489`;
* `fp` — то же, но с reporter-fingerprint target encoding в LightGBM-компонентах
  (`artifacts/probs_test_reproduced.npz`).

Регенерация `submission_equal4_m180.csv` из кэша побайтово совпала с файлом,
получившим `0.489`, поэтому источник `legacy`-ранжирования подтверждён.

## Измерения

| Семейство | Файл | k | m | LB F1 | TP(k) | avg precision | F1/2 (break-even) | marginal precision |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| fp | `submission_equal4_m140_fp.csv` | 1386 | 1.40 | 0.478959 | 569 | 0.4105 | 0.2395 | — |
| fp | `submission_equal4_m180_fp.csv` | 1782 | 1.80 | 0.485632 | 673 | 0.3777 | 0.2428 | 0.263 |
| fp | `submission_equal4_m190_fp.csv` | 1881 | 1.90 | **0.486824** | 699 | 0.3715 | 0.2434 | 0.263 |
| fp | `submission_equal4_m200_fp.csv` | 1980 | 2.00 | 0.478495 | 711 | 0.3589 | 0.2392 | 0.121 |
| legacy | `submission_equal4_m180.csv` | 1782 | 1.80 | **0.489000** | 678 | 0.3803 | 0.2445 | — |
| legacy | `submission_equal4_m190.csv` | 1881 | 1.90 | 0.485813 | 697 | 0.3708 | 0.2429 | 0.192 |
| legacy | `submission_equal4_m195.csv` | 1930 | 1.95 | 0.480546 | 702 | 0.3635 | 0.2403 | 0.102 |

`marginal precision` считается как `(TP(k) - TP(k_prev)) / (k - k_prev)`.
Расширять `k` выгодно ровно пока marginal precision выше `F1/2`.

## Выводы

1. **Reporter fingerprint на лидерборде проигрывает.** При одинаковом `k = 1782`
   `fp` даёт `TP = 673` против `678` у `legacy` (F1 `0.4856` против `0.4890`),
   при `k = 1881` — `699` против `697`, то есть паритет. Офлайн CV показывала
   `+0.003` в пользу fingerprint; на реальном тесте выигрыша нет. Это ровно тот
   вывод, который CV с fold noise `±0.001–0.002` не могла дать: разница
   `0.003` на четырёх фолдах статистически неотличима от шума.
2. **Оптимум `k` зависит от ранжирования.** У `legacy` marginal precision выше
   `1782` равна `0.192` при break-even `0.2445`, то есть расширение уже невыгодно
   и оптимум находится при `k <= 1782`. У `fp` marginal precision держится на
   `0.263` до `k = 1881` и падает до `0.121` дальше, поэтому у него оптимум
   `k = 1881`. Обе кривые очень плоские: весь исследованный диапазон
   `k = 1386…1980` лежит в пределах `F1 = 0.478…0.489`.
3. **Лучший подтверждённый результат остаётся `0.489` при `k = 1782` на
   `legacy`-ранжировании** (`submissions/submission_equal4_m180.csv`), поэтому
   `solution.py` сохраняет `RATE_MULTIPLIER = 1.8`.
4. Незакрытый шаг: точка `k = 1683` (`submission_equal4_m170.csv`) для
   `legacy`. Если там `TP >= 637`, оптимум лежит ниже `1782`, и следующая
   проверка — `k = 1584`. Ограничение платформы — 5 загрузок в сутки.

## Как воспроизвести файлы пробы

```bash
python src/make_rate_probe.py
```

Скрипт читает оба кэша тестовых вероятностей и пишет по семь файлов на семейство
(`m140 / m160 / m170 / m180 / m190 / m195 / m200`), без переобучения моделей.
